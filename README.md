# MIDI → 字幕

把 MIDI 文件里的歌词时间抠出来,在**像剪辑软件一样的多轨道时间轴**上二次编辑,然后导出成字幕文件。

导入 `.mid` → 拖动/拆分/合并对齐每一句 → 导出 SRT / VTT / LRC / 增强 LRC / ASS。

**零依赖**:没有任何 npm 包,没有构建步骤,没有框架,不用 `npm install`。只用 Node 内置模块和浏览器原生 ESM。

```
git clone <本仓库>
cd midi2srt
```

| | 服务端模式 | 静态模式 |
|---|---|---|
| 怎么跑 | 双击 **`start.bat`** | 双击 **`serve-static.bat`** |
| 或命令行 | `node server/server.mjs` | `node scripts/build-static.mjs` + `node scripts/serve-static.mjs` |
| 地址 | http://127.0.0.1:4517 | 本地预览 4518;线上则是你托管在哪就是哪 |
| 数据存哪 | 服务端磁盘 `server/data/` | 浏览器 localStorage |
| 刷新不清空 | ✅ 服务端是唯一真相 | ✅ localStorage 持久化 |
| 换设备/换浏览器 | ✅ 数据跟着服务器 | ❌ 数据跟着浏览器 |
| 多人访问同一个项目 | ✅ | ❌ |

两个 `.bat` 都是**双击即用**:自动检查 Node、清掉占用端口的旧进程(避免窗口"一闪而过"却看不出原因)、起服务、打开浏览器。窗口保持开着就是服务在跑,**关掉窗口即停止**。想换端口就传个参数:`start.bat 8080`。

> `.bat` 里的提示文字是英文的,这是刻意的:cmd.exe 按控制台代码页读脚本,UTF-8 的中文在 `.bat` 里会变乱码,除非把文件另存为 GBK —— 对一个启动器来说不值得引入这种脆弱性。

**两种模式是同一份代码**:核心逻辑全在 `lib/` 下,是浏览器原生 ESM,服务端和浏览器共用。差异只在持久化适配器 —— `public/js/store.js` 启动时探测 `GET /api/health`,通了就用服务端存,1.5 秒内不通就自动落到 localStorage。功能不缩水:项目列表、新建、打开、保存、重命名、删除、历史快照、恢复,两种模式都有。

## 它解决什么问题

MIDI 里其实**已经有**逐字的时间信息,只是没人直接给你用。歌词藏在 meta 事件里,每个音节一个事件,各自带 delta-time。但直接拿来当字幕有两个障碍:

1. **时间是 tick,不是毫秒。** 要读 `MThd` 的 division(ppq)加上轨道里所有 `FF 51` 速度事件,按 tempo map **分段积分**。用单一 BPM 线性换算,一旦有变速就会越走越偏。
2. **节拍和断句对不上。** MIDI 里每个字是等权的,没有"行"的概念。而且导唱谱常常一个字给一整拍,直接导出字幕就是一闪一闪的。

所以本工具做两件事:**按 tempo map 正确换算成毫秒**,然后**给你一个时间轴让你手动修断句和时长**。

### 实测踩过的坑(都已处理)

| 坑 | 说明 |
|---|---|
| 歌词不一定在 `0x05` | 有的文件把歌词放在 **`0x01` text** 里。逐轨判定:有 `0x05` 用 `0x05`,没有才回退到 `0x01` |
| 文本编码 | 中文 MIDI 常见 GBK。先按 UTF-8 解,出现替换字符再用 `TextDecoder('gbk')` 兜底 |
| 假歌词 | AI 生成工具的 MIDI 里有个 `FF 01` 事件塞了 AIGC 合规 JSON(`{"AIGC":{"Label":"1",…}}`),长得像歌词但不是,必须过滤 |
| 时间是 0 | 有的文件第一个歌词就在 tick 0 = 0ms。用 `if (!startMs)` 判空会把它当"未设置"丢掉,所以一律用 `Number.isFinite()` |
| 跨分钟/跨小时 | 60000ms 必须格式化成 `01:00.000` 而不是 `00:60.000`;超过一小时的时间戳各格式规则不同 |

## 操作方式

时间轴按 **MIDI 的每个 track 一条泳道**。

| 操作 | 做法 |
|---|---|
| **新建轨道** | 左侧轨道面板右上角的 **「＋ 新建轨道」** |
| **删除轨道** | 每条轨行尾的 **✕**(有片段的轨会先确认;删错了 Ctrl+Z 可撤销) |
| **调整轨道顺序** | 每条轨行尾的 **↑ / ↓** |
| **片段换轨** | **把片段往上/下拖到另一条泳道**。拖动时原位留虚线幽灵、目标泳道显示实心预览。锁定的轨不接受落点 |
| 横向平移 | 拖时间轴下方的**滚动条**;或滚轮;或拖空白处 |
| 纵向切换泳道 | 拖右侧的**滚动条**;或 **Shift+滚轮** |
| 看到整条时间轴 | 舞台工具栏的 **「适配」**(缩放并回到起点);**「开头」**回到起点 |
| 选中 | 点击片段;Shift/Ctrl 多选;空白处拖动框选 |
| 改时间 | 拖片段主体 |
| 改时长 | 拖片段左右边缘 |
| 缩放 | Ctrl+滚轮(以鼠标位置为锚点),或工具栏 − / ＋ |
| 改文本 | 双击片段就地编辑,Enter 提交 Esc 取消 |
| 拆分 / 合并 | 属性面板按钮,或按 `[` `]` 设起止 |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Y |
| 删除片段 | Delete / Backspace |
| 微调 | ← → 移动 10ms(按住 Shift 是 100ms) |
| 全选 | Ctrl+A |

拖动片段时会**吸附**到:其它片段的边界、整秒、以及该片段**原始的 MIDI 时间**(好让你随时对回原谱)。
**一次拖动只产生一条撤销记录** —— 横向改时间、纵向换轨,甚至两者同时,都只算一步。

### 打开指定项目

```
http://127.0.0.1:4517/?project=<项目 id>
```

`?project=new` 强制开一个空项目。不带参数时自动恢复上次打开的项目;若上次离开时还有没写入服务端的改动,会用本地镜像恢复并明确提示。

## 「刷新不清空」是怎么保证的

编辑到一半误按 F5 就白干,是这个工具最不能忍的事。所以做了四层,因为浏览器**不保证** `beforeunload` 里的异步请求能发出去,光靠防抖是堵不住"改完立刻刷新"这个窄缝的:

| 层 | 机制 | 堵住的场景 |
|---|---|---|
| 1 | 所有改动 debounce 300ms 自动存后端 | 正常编辑 |
| 2 | `visibilitychange`(hidden)/ `pagehide` 时**立即** flush | 切标签页、关窗口 |
| 3 | **每次改动同步写 localStorage 镜像** | 300ms 窗口内正好刷新 —— 这一层是关键 |
| 4 | `beforeunload` 未保存时拦一道 | 兜底提示 |

启动时如果服务端不可用,或服务端 revision 落后于本地镜像,会用镜像恢复并**明确提示**,不静默。保存失败会标红、写本地备份、每 3 秒重试,不会悄悄丢。

服务端落盘是**原子**的(写 `.tmp` → `fsync` → `rename`),写到一半断电不会毁掉项目文件;每次保存留一份快照,保留最近 30 个,可以一路退回。同一项目的并发写入由一条队列串行化。

## 导出格式

| 格式 | 样子 | 用途 |
|---|---|---|
| **SRT** | `00:00:20,786 --> 00:00:21,286` | 视频字幕,通用 |
| **VTT** | `00:00:20.786 --> 00:00:21.286` | 网页 `<track>`,首行 `WEBVTT` |
| **LRC** | `[00:20.78]慵` | 音乐播放器歌词,行级 |
| **增强 LRC** | `[00:20.78]<00:20.78>慵<00:21.28>懒` | 逐字卡拉OK |
| **ASS** | `{\k50}慵` | 带样式,可做卡拉OK 变色;`\k` 单位是厘秒 |

导出会尊重轨道的**可见**开关,隐藏的轨不导出。

## 静态部署

`node scripts/build-static.mjs` 会把 `dist/static/` 构建成一个**可以整个丢上去**的站点根 —— 放到 GitHub Pages / Vercel / Netlify / 任意 nginx 即可,不用再往下进一层。

构建时会做两件事:把 `public/` 的内容铺到根上、`lib/` 放在旁边,并把 `js/*.js` 里指向 lib 的 `../../lib/` 重写成 `../lib/`(扁平布局下的相对路径变化);然后自检两道 —— 逐层解引用所有 JS import 与 HTML 的 `src`/`href`,以及禁止除探测之外的绝对 `/api` 依赖。

静态版没有后端,数据存在浏览器 localStorage 里。换浏览器或清站点数据会丢,重要项目请备份,或者改用服务端模式。

**注意**:不能 `file://` 直接双击 `index.html` 打开。ES module 在 `file://` 下会被 CORS 拦掉,必须走 HTTP —— 本地预览也得用 `node scripts/serve-static.mjs` 或任意静态服务器。

## 配置

服务端支持这些参数(带"环境变量"的可以用环境变量代替):

| 参数 | 环境变量 | 作用 |
|---|---|---|
| `--port <n>` | `DSH_SUB_PORT` | 监听端口,默认 4517;`--port 0` 由系统分配并打印实际端口 |
| `--host <h>` | — | 监听地址,默认 `127.0.0.1` |
| `--root <dir>` | `DSH_SUB_ROOT` | 静态文件根,默认仓库根 |
| `--data-dir <dir>` | `DSH_SUB_DATA_DIR` | 项目数据目录,默认 `server/data` |
| `-h`, `--help` | — | 显示帮助 |

`node server/server.mjs --help` 会打印同样这份说明。

## 已知限制

- **没有音频、波形和播放。** 这是刻意的:对齐只能看数字和原始 MIDI 时间。想跟着听,自己开个播放器。
- **不做人声分离或音频识别。** 只处理 MIDI 里已有的歌词事件。
- **静态模式的数据只在本浏览器。** 换浏览器或清站点数据就没了。
- **服务端没有鉴权。** 只监听本地或你信任的网络,别直接暴露到公网。
- **MIDI 格式**:支持 SMF type 0/1,不支持 type 2(多序列,极罕见)。
- 编码兜底只覆盖 UTF-8 与 GBK,其它编码(如 Shift-JIS)可能乱码。
